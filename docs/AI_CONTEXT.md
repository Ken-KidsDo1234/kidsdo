## สถานะปัจจุบัน (อัปเดต 2026-11-20)

### บันทึกงานล่าสุด (2026-11-20)

**งานที่ทำแล้ว**

- ปรับเมนูเว็บไซต์ใน `Index.html` ให้ทันสมัยขึ้น รองรับเมนูบนมือถือ และเพิ่มสถานะโฟกัสสำหรับคีย์บอร์ด
- เพิ่มฟอร์มจัดการ Popup ใน `Index.html` เพราะเดิมกดเพิ่มแล้วเห็นเพียง JSON เริ่มต้น `{"status":"published"}`
- เพิ่มเมนู Admin “คลังไฟล์” และอัปโหลดเพลง ภาพ เอกสารเข้าโฟลเดอร์ Google Drive ตามหมวดใน `Index.html` และ `Files.js` จำกัดชนิดไฟล์ตามหมวดและขนาดไม่เกิน 15 MB พร้อมนับจำนวนไฟล์
- แก้ `PublicPages.html`: หน้าปฏิทินถูกซ่อนด้วย `display:none` ก่อนย้ายไปหน้า route ใหม่ จึงเปิดการแสดงผลกลับหลังย้าย
- เพิ่มข้อความแจ้งเตือนใน `Index.html` เมื่อเปิดไฟล์ตรงจากเครื่อง แทนการเปิดผ่าน Google Apps Script ซึ่งทำให้ `google.script.run` ไม่มีและอ่าน Google Sheets ไม่ได้
- ผู้เข้าชมทั่วไปอ่านข้อมูลได้อย่างเดียว; ข่าว/กิจกรรมที่แสดงต้องมีสถานะ `published` หรือ `active`; การแก้ไขยังอยู่หลังระบบ Login และตรวจ Role ฝั่ง server
- แก้ `Index.html` โดยเอา wrapper `#publicApp` ที่ซ้ำออก เพื่อไม่ให้หน้า Login/Admin ถูกซ่อนตาม public shell
- ปรับ `PublicData.js` ให้ตรวจสถานะเผยแพร่แบบตัดช่องว่างและไม่สนตัวพิมพ์ พร้อมเรียงข่าว/กิจกรรมจากค่า Date จริงและให้วันที่ว่างอยู่ท้ายรายการ
- อ่านภาพอ้างอิงใน `docs/images/` และภาพประกอบใน `docs/`; สรุปข้อกำหนดและ data flow ไว้ใน `IMAGE_ASSETS.md` พร้อมกำหนดให้ AI ทุกตัวอ่านก่อนแก้ UI/ข้อมูล
- ภาพ flow ข่าวระบุการเก็บ metadata ใน Google Sheets และไฟล์ภาพใน Google Drive; ปัจจุบัน News editor รับ URL `coverImage` แต่ยังไม่มีปุ่มอัปโหลดภาพข่าวตรงจากหน้า Admin

**ผลตรวจที่ทำแล้ว**

- ตรวจ JavaScript syntax ของ `Index.html`, `PublicPages.html` และ `Files.js` ผ่าน
- ทดสอบ route ปฏิทินว่ากลับมาแสดงหลังย้ายหน้า และกลับหน้าแรกได้
- ทดสอบ logic อัปโหลดด้วย mock สำหรับเพลง/ภาพ/เอกสาร และตรวจการปฏิเสธ MIME/นามสกุลที่ไม่ตรง
- `git diff --check` ผ่าน
- ทดสอบ mock การกรองสถานะและเรียงวันที่ รวมถึง syntax ของ inline scripts ใน `Index.html`/`PublicPages.html` ผ่าน
- ตรวจ URL `/exec` ที่แชร์ใน browser ล่าสุดแล้ว: ภาพหน้าจอเห็นส่วนหัว เมนู ปุ่มเข้าสู่ระบบ/สมัครสมาชิก และภาพหลัก แต่ snapshot อ่านเนื้อหาใน sandbox iframe ไม่ได้และมี page error จึงยังยืนยันข่าว/กิจกรรมจาก Google Sheets หรือโค้ดที่ deploy อยู่ไม่ได้
- ยังไม่ได้ทดสอบกับ Google Apps Script deployment, Google Sheets หรือ Google Drive จริง และยังไม่ได้สร้าง deployment version ใหม่
- ตรวจ diff ที่แก้ค้างทั้งหมดแล้ว; ยังไม่ deploy เพราะมีความเสี่ยงจากการติดตั้งระบบสื่อสารที่ยังไม่ยืนยัน, การสมัคร username ซ้ำเมื่อมีคำขอพร้อมกัน และข้อความค้างเมื่ออัปโหลดไฟล์แนบล้มเหลว

**สิ่งที่ต้องทำครั้งต่อไป**

**กติกาลำดับงาน — ห้ามข้ามเงื่อนไขโดยไม่แจ้งผู้ใช้**

- ตรวจสถานะของขั้นก่อนหน้าก่อนเริ่มขั้นถัดไป; ขั้น 1 และการตรวจ diff ในขั้น 4 เป็นเงื่อนไขก่อน deploy
- ถ้าผู้ใช้ขอให้ทำงานที่ข้ามขั้นที่ยังไม่เสร็จ ให้หยุดและแจ้งว่าขั้นใดยังไม่ผ่าน ความเสี่ยงคืออะไร และต้องการให้ยืนยันการข้ามก่อน ห้ามข้ามหรือ deploy เงียบ ๆ
- การเห็นส่วนหัวหรือภาพหลักของเว็บไม่ถือว่ายืนยันว่าข่าว/กิจกรรมจาก Google Sheets ทำงานแล้ว

1. ทดสอบข้อมูลจริงจาก Google Sheets ผ่าน URL `/exec`: ข่าวและกิจกรรม `published`/`active` ต้องแสดง, `draft`/`pending` ต้องไม่แสดง, ตรวจลำดับวันที่และปฏิทิน; หาสาเหตุ page error/iframe ที่อ่านเนื้อหาไม่ได้
2. ก่อน deploy ฟีเจอร์สื่อสาร ให้ยืนยันใน Apps Script Editor ว่า `installKidsCommunications()` ทำงานและสร้าง Sheets/โฟลเดอร์ที่จำเป็นครบ
3. แก้และทดสอบความเสี่ยงที่พบใน diff: ล็อกการตรวจ/สร้าง username ใน `Members.js`; ตรวจสอบไฟล์แนบก่อนบันทึกข้อความหรือ rollback เมื่ออัปโหลดไม่สำเร็จใน `MemberComms.js`
4. ตรวจ diff ที่ค้างทั้งหมดอีกครั้งก่อน deploy เพราะ `clasp push` จะส่งไฟล์โครงการทั้งหมด ไม่ใช่เฉพาะ `Index.html`/`PublicData.js`; สร้าง version และอัปเดต deployment หลังยืนยันชุดไฟล์ที่จะเผยแพร่แล้วเท่านั้น
5. พิจารณาเพิ่มการอัปโหลดภาพข่าวจาก Admin ไป Google Drive `News` folder แล้วบันทึก file ID/URL ลง Sheet; ตอนนี้ editor รับ URL `coverImage` เท่านั้น
6. ก่อน commit/push ให้ทบทวนไฟล์เปลี่ยนแปลงทั้งหมดและแบ่ง commit ตามงาน; การ push จะทำให้เอกสารที่ติดตามใน GitHub พร้อมให้ AI ที่เปิด repository อ่าน แต่ไม่ได้ซิงก์ความจำหรือบังคับให้ AI ทุกบริการอ่านเอง

### การแชร์บริบทให้ AI ผ่าน Git

- Repository หลัก: `https://github.com/Ken-KidsDo1234/kidsdo` (branch `main`)
- ข้อมูลที่ต้องแชร์ควรอยู่ในไฟล์ที่ commit แล้ว เช่น `docs/Project.md`, `docs/AI_CONTEXT.md`, `docs/ARCHITECTURE.md` และ `docs/IMAGE_ASSETS.md`
- หลังตรวจ diff ให้ commit และ push ไป GitHub; AI ต้องเปิด repository/branch ล่าสุดและอ่านเอกสารเหล่านี้ก่อนเริ่มงาน
- GitHub ไม่ได้ส่งเนื้อหาให้ AI ทุกตัวโดยอัตโนมัติ และการ push ไม่ได้อัปเดตความจำของ AI; ให้ตั้ง project instructions ในแต่ละบริการหรือสั่ง AI ให้อ่านเอกสารใน repository

- ปัญหาเดิมที่เปิดเว็บได้แต่เมนูและ Login ใช้งานไม่ได้ เกิดจาก JavaScript ใน HTML ที่ Apps Script สร้างขึ้นมี `&lt;` แทนเครื่องหมาย `<` ทำให้ script parse ไม่ผ่านและฟังก์ชัน เช่น `openLogin()` ไม่ถูกประกาศ
- พบ syntax error แยกต่างหากใน `AdminTools.js` ซึ่งขวางการ push/deploy; แก้ไขแล้ว ไม่ใช่สาเหตุ runtime เดียวกับ JavaScript ใน browser
- แก้ Contact route ที่ขาด `safeExternalUrl()` แล้ว
- Deployment เดิมคือ version 33 จากการยืนยันก่อนหน้า แต่เมื่อทดสอบการสมัครสมาชิกและระบบสื่อสารจึง Push โค้ดและสร้าง version 34 แล้วอัปเดต Deployment เดิมไปยัง version 34
- หน้า Live version 34 แสดงปุ่ม “สมัครสมาชิก” เพิ่มแล้ว และทดสอบเปิดหน้าสมัคร/หน้าล็อกอินพร้อม validation ผ่าน
- ระบบสมาชิกพื้นฐานพร้อม Pending/Approve/Reject และหน้าสมัครสไตล์ใหม่ใน `Index.html`/`Members.js`
- ระบบสื่อสารสมาชิกต่อยอดใน `MemberComms.js`/`MemberCommsUI.html` ประกอบด้วยห้องสนทนา ข้อความส่วนตัว กระดานโพสต์ ติดต่อ Admin การลบข้อความ และฟังก์ชัน Admin สร้าง/แก้ไข/ลบห้อง
- เพิ่มฟิลด์ Audit ของห้องใน schema `ChatRooms`: `deletedAt`, `deletedBy`, `deleteReason`
- ทดสอบ syntax JavaScript ของ Backend และ HTML ผ่าน แต่ยังไม่ได้ทดสอบการสร้างบัญชีจริง การส่งข้อความจริง และการลบห้องจริง
- ผู้ใช้ยืนยันก่อนหน้านี้ว่า Login/Admin/logout, เมนู และภาพพื้นหลัง `Black ground2.jpg` ใช้งานได้
- ผู้ใช้เริ่มกรอกข้อมูลข่าว/กิจกรรมและรายงานว่ายังไม่เห็นบนเว็บไซต์; ตรวจพบว่า browser ที่แชร์เปิด `file:///F:/Projects/KidsDo/Index.html` จึงยืนยันได้เฉพาะว่าไฟล์ local อ่าน Google Sheets ไม่ได้ ยังต้องทดสอบข้อมูลจริงผ่าน URL `/exec`
